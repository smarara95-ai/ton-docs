# Solidity مقابل FunC

يتضمن تطوير العقود الذكية استخدام لغات محددة مسبقًا مثل Solidity لـ Ethereum و FunC لـ TON.
Solidity هي لغة كائنية التوجه، عالية المستوى، ذات كتابة صارمة (strictly typed)، تأثرت بلغات C++ و Python و JavaScript. صُممت خصيصًا لكتابة العقود الذكية على منصات بلوكتشين Ethereum.

FunC هي لغة عالية المستوى تُستخدم لبرمجة العقود الذكية على TON Blockchain. وهي لغة خاصة بمجال معين (domain-specific)، شبيهة بلغة C، ذات كتابة ثابتة (statically typed).

فيما يلي، نحلل بإيجاز أنواع البيانات، والتخزين، والدوال، والتحكم في التدفق، والقواميس (hashmaps).

## الاختلافات بين Solidity و FunC
### تخطيط التخزين

#### Solidity
تخزّن Solidity متغيرات الحالة في تخزين مسطح من نوع مفتاح-قيمة، حيث تكون كل خانة (slot) كلمة من 256 بت. تُرقَّم الخانات بالتتابع بدءًا من الصفر، ويحدد ترتيب الإعلان (مع قواعد الحزم packing) تخصيص الخانات. تحدد الكلمة المفتاحية `storage` موقع البيانات للأنواع المرجعية؛ ولا تحدد التخطيط.

#### FunC
تُخزَّن بيانات التخزين الدائم في TON Blockchain كخلية (cell). تلعب الخلايا دور الذاكرة في TVM القائم على المكدس (stack-based). لقراءة البيانات من خلية، تحتاج إلى تحويل الخلية إلى شريحة (slice) ثم الحصول على بتات البيانات والمراجع إلى خلايا أخرى عن طريق تحميلها من الشريحة. لكتابة البيانات، يجب عليك تخزين بتات البيانات والمراجع إلى خلايا أخرى في باني (builder) وتحويل الباني إلى خلية جديدة.

### أنواع البيانات

#### Solidity
تتضمن Solidity أنواع البيانات الأساسية التالية:
- الأعداد الصحيحة **الموقّعة (Signed)** و**غير الموقّعة (Unsigned)**
- **Boolean**
- **العناوين (Addresses)**، وعادةً ما تكون حوالي 20 بايت، وتُستخدم لتخزين عناوين محفظة Ethereum أو العقد الذكي. إذا كان النوع `address payable`، يمكن للعنوان استقبال Ether عبر `.transfer` و `.send`.
- **مصفوفات البايت** — `bytes` هي مصفوفة بايت ذات حجم ديناميكي؛ مصفوفات البايت ذات الحجم الثابت هي `bytes1` … `bytes32`.
- **الحرفيات (Literals)** — حرفيات صحيحة، ونصية، وسداسية عشرية، وعناوين.
- **Enums**
- **المصفوفات (Arrays)** — ثابتة أو ديناميكية
- **Structs**
- **Mappings**

#### FunC
في حالة FunC، أنواع البيانات الرئيسية هي:
- **الأعداد الصحيحة (Integers)**
- **Cell** — بنية البيانات الأساسية غير الشفافة في TON، تحتوي على ما يصل إلى 1023 بت وحتى 4 مراجع لخلايا أخرى
- **Slice** و **Builder** — طرق عرض متخصصة للقراءة من الخلايا والكتابة إليها.
- **Continuation** — استمرارية TVM تُستخدم لإدارة تدفق التنفيذ.
- **Tuples** — مجموعة مرتبة من حتى 255 عنصرًا، ذات أنواع قيم عشوائية، وربما مميزة.
- **Tensors** — مجموعة مرتبة جاهزة للتعيين الجماعي مثل: `(int, int) a = (2, 4)`. حالة خاصة من نوع tensor هي نوع الوحدة `()`. وهو يمثل أن الدالة لا تعيد أي قيمة أو ليس لها أي وسائط.

حاليًا، لا تدعم FunC تعريف أنواع مخصصة. اقرأ المزيد عن الأنواع في صفحة [التعليمات (Statements)](/v3/documentation/smart-contracts/func/docs/statements/).

### إعلان المتغيرات واستخدامها

#### Solidity
Solidity لغة ذات كتابة ثابتة (statically typed)، مما يعني أنه يجب تحديد نوع كل متغير عند الإعلان عنه.

```js
uint test = 1; // Declaring an unsigned variable of integer type
bool isActive = true; // Logical variable
string name = "Alice"; // String variable
```

#### FunC
FunC لغة أكثر تجريدًا وموجّهة نحو الدوال. وهي ذات كتابة ثابتة وتدعم استنتاج النوع (type inference) (مثل `var`).

```func
(int x, int y) = (1, 2); // A tuple containing two integer variables
var z = x + y; // Type‑inferred variable declaration
```

اقرأ المزيد في صفحة [التعليمات (Statements)](/v3/documentation/smart-contracts/func/docs/statements/).

### الحلقات (Loops)

#### Solidity
تدعم Solidity حلقات `for` و `while` و `do { ... } while`.

إذا كنت تريد تنفيذ شيء ما 10 مرات، يمكنك القيام بذلك على هذا النحو:

```js
uint x = 1;

for (uint i; i < 10; i++) {
    x *= 2;
}

// x = 1024
```

#### FunC
تدعم FunC، بدورها، حلقات `repeat` و `while` و `do { ... } until`. لا تدعم FunC حلقة `for`. إذا كنت تريد تنفيذ نفس الكود الموجود في المثال أعلاه في FunC، يمكنك استخدام `repeat`

```func
int x = 1;
repeat(10) {
  x *= 2;
}
;; x = 1024
```
اقرأ المزيد في صفحة [التعليمات (Statements)](/v3/documentation/smart-contracts/func/docs/statements/).

### الدوال (Functions)

#### Solidity

تتعامل Solidity مع إعلانات الدوال بمزيج من الوضوح والتحكم. في لغة البرمجة هذه، تبدأ كل دالة بالكلمة المفتاحية `function`، متبوعةً باسم الدالة ومعاملاتها. جسم الدالة محاط بأقواس معقوفة، مما يحدد بوضوح النطاق التشغيلي. بالإضافة إلى ذلك، تُشار قيم الإرجاع باستخدام الكلمة المفتاحية `returns`.

ما يميز Solidity هو تصنيفها لرؤية الدوال — يمكنك تحديد الدوال كـ `public` أو `private` أو `internal` أو `external`. تحدد هذه التعريفات الشروط التي بموجبها يمكن للمطورين الوصول إلى أجزاء أخرى من العقد أو الكيانات الخارجية واستدعائها. فيما يلي مثال نقوم فيه بتعيين المتغير العام `num` بلغة Solidity:

```js
function set(uint256 _num) public returns (bool) {
    num = _num;
    return true;
}
```

#### FunC
بالانتقال إلى FunC، يُعد برنامج FunC في الأساس قائمة من إعلانات/تعريفات الدوال وإعلانات المتغيرات العامة. يبدأ إعلان دالة FunC عادةً بمُعلِن اختياري، متبوعًا بنوع الإرجاع واسم الدالة.

تُدرَج المعاملات بعد ذلك، وينتهي الإعلان بمجموعة من المحددات (specifiers) — مثل `impure` و `inline/inline_ref` و `method_id`. تعدّل هذه المحددات رؤية الدالة، وقدرتها على تعديل تخزين العقد، وسلوك التضمين (inlining). فيما يلي مثال نقوم فيه بتخزين متغير تخزين كخلية في التخزين الدائم بلغة FunC:

```func
() save_data(int num) impure inline {
  set_data(begin_cell()
            .store_uint(num, 32)
           .end_cell()
          );
}
```
اقرأ المزيد في صفحة [الدوال (Functions)](/v3/documentation/smart-contracts/func/docs/functions/).

### هياكل التحكم في التدفق

#### Solidity
تتوفر في Solidity معظم هياكل التحكم المعروفة من اللغات ذات الأقواس المعقوفة، بما في ذلك: `if` و `else` و `while` و `do` و `for` و `break` و `continue` و `return`، بالدلالات المعتادة المعروفة من C أو JavaScript.

#### FunC
تدعم FunC عبارات `if-else` الكلاسيكية، و `ifnot`، و `repeat`، و `while`، وحلقات `do/until`. كما تدعم، منذ الإصدار v0.4.0، عبارات `try-catch`.

اقرأ المزيد في صفحة [التعليمات (Statements)](/v3/documentation/smart-contracts/func/docs/statements/).

### القواميس (Dictionaries)

بنية بيانات القاموس أو جدول التجزئة (hashmap) ضرورية لتطوير عقود Solidity و FunC لأنها تتيح للمطورين تخزين البيانات واسترجاعها بكفاءة في العقود الذكية، وتحديدًا البيانات المرتبطة بمفتاح معين، مثل رصيد المستخدم أو ملكية أصل ما.

#### Solidity

Mapping هو جدول تجزئة في Solidity يخزّن البيانات كأزواج مفتاح-قيمة، حيث يمكن أن يكون المفتاح أيًا من أنواع البيانات المضمّنة، باستثناء الأنواع المرجعية، ويمكن أن تكون قيمة نوع البيانات من أي نوع. في Solidity وعلى بلوكتشين Ethereum، تربط عمليات التعيين (mappings) عادةً عنوان Ethereum فريدًا بنوع قيمة مقابل. في أي لغة برمجة أخرى، يعادل التعيين (mapping) القاموس (dictionary).

في Solidity، لا تملك التعيينات طولًا أو مفهوم تعيين مفتاح أو قيمة. يمكن إعلان التعيينات فقط في التخزين (متغيرات الحالة)؛ ولا يُسمح بها في الذاكرة. عند تهيئة التعيينات، فإنها تتضمن كل مفتاح ممكن وتُعيَّن إلى قيم تكون تمثيلاتها بالبايت كلها أصفار.

#### FunC

نظير التعيينات (mappings) في FunC هو القواميس أو جداول تجزئة TON. في سياق TON، جدول التجزئة (hashmap) هو بنية بيانات تُمثَّل بشجرة من الخلايا. يقوم جدول التجزئة بتعيين المفاتيح إلى قيم من أنواع عشوائية بحيث يكون البحث السريع والتعديل ممكنين. التمثيل المجرد لجدول التجزئة في TVM هو شجرة باتريشيا (Patricia tree) أو شجرة ثنائية مضغوطة (trie).

يمكن أن يؤدي العمل مع أشجار خلايا كبيرة محتملة إلى عدة مشاكل. تبني كل عملية تحديث عددًا كبيرًا من الخلايا (كل خلية مبنية تكلف 500 غاز)، مما يعني أن هذه العمليات قد تنفد مواردها إذا استُخدمت بلا حذر. لتجنب تجاوز حد الغاز، قلّل عدد تحديثات القاموس في معاملة واحدة.

كذلك، تحتوي شجرة ثنائية لأزواج `N` من المفاتيح والقيم على `N-1` تفرعات، مما يعني ما لا يقل عن `2N-1` خلية بشكل إجمالي. يقتصر تخزين العقد الذكي على `65536` خلية فريدة، لذا فإن الحد الأقصى لعدد الإدخالات في القاموس هو `32768`، أو أكثر قليلاً إذا كانت هناك خلايا متكررة.

اقرأ المزيد عن [القواميس في TON](/v3/documentation/smart-contracts/func/docs/dictionaries/).

### التواصل بين العقود الذكية

توفر Solidity و FunC نهجين مختلفين للتفاعل مع العقود الذكية. يكمن الاختلاف الرئيسي في آليات الاستدعاء والتفاعل بين العقود.

#### Solidity

تستخدم Solidity عقودًا كائنية التوجه تتفاعل مع بعضها البعض من خلال استدعاءات الطرق (method calls). يشبه هذا التصميم استدعاءات الطرق في لغات البرمجة الكائنية التوجه التقليدية.

```js
// External contract interface
interface IReceiver {
    function receiveData(uint x) external;
}

contract Sender {
    function sendData(address receiverAddress, uint x) public {
        IReceiver receiver = IReceiver(receiverAddress);
        receiver.receiveData(x);  // Direct call of the contract function
    }
}
```

#### FunC

تعمل FunC، المستخدمة في نظام بلوكتشين TON البيئي، على أساس الرسائل لاستدعاء العقود الذكية والتفاعل بينها. بدلاً من استدعاء الطرق مباشرة، ترسل العقود رسائل إلى بعضها البعض، والتي يمكن أن تحتوي على بيانات وكود للتنفيذ.

لنأخذ مثالاً حيث يجب على عقد ذكي مُرسِل إرسال رسالة تحتوي على رقم، ويجب على عقد ذكي مستقبِل استقبال ذلك الرقم وإجراء بعض المعالجة عليه.

في البداية، يجب على العقد الذكي المستقبِل وصف كيفية استقباله للرسائل.

```func
() recv_internal(int my_balance, int msg_value, cell in_msg, slice in_msg_body) impure {
    int op = in_msg_body~load_uint(32);

    if (op == 1) {
        int num = in_msg_body~load_uint(32);
        ;; do some manipulations
        return ();
    }

    if (op == 2) {
        ;;...
    }
}
```

**تدفق استقبال الرسالة:**
1. يُستدعى `recv_internal()` عندما يستقبل العقد رسالة داخلية واردة.
2. المعاملات: رصيد العقد، وقيمة الرسالة، وخلية الرسالة الأصلية، وشريحة `in_msg_body` — وهي جسم الرسالة المستلمة.
3. سيخزّن جسم رسالتنا رقمين صحيحين. الرقم الأول هو عدد صحيح غير موقّع من 32 بت يُدعى `op` ويحدد عملية العقد الذكي. يمكنك رسم بعض التشابه مع Solidity واعتبار `op` توقيع دالة (function signature).
4. نستخدم `load_uint()` لقراءة `op` كرقم من الشريحة الناتجة.
5. بعد ذلك، ننفذ منطق الأعمال للعملية المعطاة. لاحظ أننا حذفنا هذه الوظيفة في هذا المثال.


بعد ذلك، يجب على العقد الذكي للمُرسِل إرسال الرسالة بشكل صحيح. يتحقق هذا باستخدام `send_raw_message`، الذي يتوقع رسالة مسلسَلة (serialized) كوسيطة.

```func
int num = 10;
cell msg_body_cell = begin_cell().store_uint(1,32).store_uint(num,32).end_cell();

var msg = begin_cell()
            .store_uint(0x18, 6)
            .store_slice(addr) ;; in the example, we hardcode the recipient's address
            .store_coins(0)
            .store_uint(0, 1 + 4 + 4 + 64 + 32 + 1 + 1)
            .store_ref(msg_body_cell)
        .end_cell();

send_raw_message(msg, mode);
```
**تدفق إرسال الرسالة:**
1. في البداية، نحتاج إلى بناء رسالتنا. يمكن العثور على البنية الكاملة للإرسال [هنا](/v3/documentation/smart-contracts/message-management/sending-messages/).
2. يمثل جسم الرسالة خلية. في `msg_body_cell` نقوم بما يلي: `begin_cell()` - ينشئ باني (builder) للخلية المستقبلية، أول `store_uint` - يخزّن أول uint في الباني (1 - وهذا هو `op` الخاص بنا)، ثاني `store_uint` - يخزّن ثاني uint في الباني (num - وهذا هو رقمنا الذي سنعالجه في العقد المستقبِل)، `end_cell()` - ينشئ الخلية.
3. لإرفاق الجسم الذي سيصل في `recv_internal` ضمن الرسالة، نشير إلى الخلية المُجمَّعة في الرسالة نفسها باستخدام `store_ref`.
4. إرسال الرسالة.

يوضح هذا المثال كيف يمكن للعقود الذكية التواصل مع بعضها البعض.
